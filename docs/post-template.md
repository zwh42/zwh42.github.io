# 撰写技术文章

复制下面的内容到 `_posts/YYYY-MM-DD-your-title.md`。日期使用实际发布日期。

```markdown
---
layout: post
title: "技术对象与分析范围"
date: 2026-10-25
author: 端点星日志
description: "概括文章分析的问题、方法与适用范围。"
tags: [技术]
toc: true
---

直接写引言，页面会自动显示文章标题。

## 问题定义与假设

正文。

## 方法与分析

正文。

## 参考文献

1. 作者. 文献题名. 期刊或出版机构, 年份. DOI 或原文链接。
```

- `img` 可选，路径相对 `assets/img/`。没有封面图也能正常显示。
- `toc: true` 显示可展开的文章目录。
- `mathjax: true` 启用公式，支持 `$...$` 和 `$$...$$`。
- `mermaid: true` 启用 Mermaid 图表。
- 分类、标签及其文章数量在构建时自动汇总到 `/categories/`。
- `categories: [分类名]` 可选；省略时会按标题和已有标签匹配 `_data/taxonomy.yml` 中的规则，没有匹配则归入“随笔”。
- `tags` 可选；省略时按标题和摘要中的关键词提取。已有标签会优先保留，规则在 `_data/taxonomy.yml` 中维护。
- 标题、摘要、分类、标签和正文都会参与搜索。

技术文章应围绕明确的问题组织论证。导语直接交代技术对象、分析范围和主要结论；章节按定义、推导、方法、结果及工程边界展开，不必机械套用同一结构。少用设问、对话提示和重复总结，保留必要的解释与例子。

公式首次出现时定义符号、单位、坐标和近似条件。区分原文结果、本文推导与工程归纳，实验数值应附测试范围，性能判断应说明比较基准。正文在相关论断处引用文献，文末列出作者、题名、出版信息及 DOI 或原始文档链接。

配图使用可复用的 Wikimedia Commons、教材或正式技术文档原图。图注注明作者、原始文件页或教材图号及页码、许可和修改情况；不以自行绘制的示意图替代来源图，也不把原理示意图当作实验结果。
