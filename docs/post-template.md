- `img` 可选，路径相对 `assets/img/`。没有封面图也能正常显示。
- `toc: true` 显示可展开的文章目录。
- `mathjax: true` 启用公式，支持 `$...$` 和 `$$...$$`。
- `mermaid: true` 启用 Mermaid 图表。
- 分类、标签及其文章数量在构建时自动汇总到 `/categories/`。
- `categories: [分类名]` 可选；省略时会按标题和已有标签匹配 `_data/taxonomy.yml` 中的规则，没有匹配则归入“随笔”。
- `tags` 可选；省略时按标题和摘要中的关键词提取。已有标签会优先保留，规则在 `_data/taxonomy.yml` 中维护。
- 标题、摘要、分类、标签和正文都会参与搜索。

技术文章应围绕明确的问题组织论证。导语直接交代技术对象、分析范围和主要结论；章节按定义、推导、方法、结果及工程边界展开，不必机械套用同一结构。少用设问、对话提示和重复总结，保留必要的解释与例子。

每篇文章必须自成体系：在本篇定义所需的术语、符号、物理假设和评价指标，并给出理解核心结论所需的推导或解释。不添加阅读路线、系列阅读、先修文章或其他本站文章的互引；不得用“参见另一篇”代替本篇必要内容。引用应指向原始论文、教材或正式技术文档，配图来源与许可同样在本篇注明。

公式首次出现时定义符号、单位、坐标和近似条件。区分原文结果、本文推导与工程归纳，实验数值应附测试范围，性能判断应说明比较基准。正文在相关论断处引用文献，文末列出作者、题名、出版信息及 DOI 或原始文档链接。

配图使用可复用的 Wikimedia Commons、教材或正式技术文档原图，不使用 AI 直接生成的技术配图。图注注明作者、原始文件页或教材图号及页码、许可和修改情况，也不把原理示意图当作实验结果。允许在原许可范围内使用 AI 辅助降噪、清晰度增强等处理，但应保留原图，在图注说明处理方法，并核对处理前后的几何、曲线、文字、数字和物理含义；不得补绘不可辨认的实验细节。图片登记在 `assets/images/references/SOURCES.json`，记录原始链接、许可、修改方式及文件哈希。

图片和出处使用同一 `figure` 元素，图注紧邻原图：

```html
<figure class="technical-figure">
  <div class="figure-image"><img src="/assets/images/references/example.png" alt="说明图中技术内容" loading="lazy" decoding="async"></div>
  <figcaption markdown="span">图 1：图意。作者，年份，[原始文件页或教材页码](原文链接)，[复用许可](许可链接)。原图未修改。</figcaption>
</figure>
```

数学变量使用 `$...$`，独立公式使用单独成段的 `$$...$$`，不要用公式截图。分式、向量、上下标及单位保持规范；较长的推导优先用 `aligned` 按等号或运算关系分行。避免为适应手机屏幕缩小字号，超长公式由局部滚动容器承载。公式前交代假设，公式后解释符号和结论。
