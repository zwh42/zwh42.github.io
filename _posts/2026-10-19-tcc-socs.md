先算一笔很粗的账。

假设一颗芯片 20 mm 见方，用 10 nm 的 grid 铺满它，每边两百万个点，整张图就有 4 万亿个采样点。单精度存一张图要 16 TB。Aerial image 还没开始算，内存先扛不住了。

实际生产当然不会这么干，但这道算术题把问题摆得很清楚：mask 面积很大，局部图形又很细，OPC 还要反复移动 edge、重新成像。Full-chip computational lithography 要是只靠更快的机器硬顶，很早就会撞墙。

TCC（Transmission Cross Coefficient）和 SOCS（Sum of Coherent Systems）经常被当成这道题的答案。说准确一点，它们只完成了其中最关键的一次改写。SOCS 没有压缩 layout，也没有把 wafer 上的图像降成低分辨率。它压缩的是光学系统本身，具体说，是 spatial frequency 之间两两耦合的那套规则。

这句话有点硬，我们从 partial coherence 下怎样成像讲起。

## 一个 source point，对应一幅 coherent image

照明 source 有面积。Annular、dipole、quadrupole 和 freeform source，都可以看成许多彼此不相干的 source point。对其中一个点，mask 的 complex amplitude 经过 projection lens 的 pupil 滤波，在 wafer 面形成一个 coherent 电场，取模平方就是这个点贡献的强度。把所有 source point 的强度加起来，就是 partially coherent 的 aerial image。

这就是 Abbe formulation。物理图像很直观，麻烦也很直观：source 采得越密，要重复的 coherent imaging 就越多；每换一张 mask、每做一次 OPC iteration，这批工作都要再来一遍。

Partially coherent source 虽然有很多 source point，经过有限的 pupil 以后，它们的响应高度相关。最大的几个 eigenmode 先拿走大部分能量，后面的 eigenvalue 往往衰减得很快。这种分解思路最早可以追溯到 Gamo 用矩阵处理 partial coherence 的工作；Pati 和 Kailath 1994 年把它叫做 OCA（optimal coherent approximation）；Cobb 1998 年在 UC Berkeley 的博士论文里用 SVD 做了数值实现，并把这套结构命名为 SOCS。同一篇论文还提出了 VTR（variable threshold resist）model。

换句话说，SOCS 把一个描述频率两两耦合的四维 TCC，近似成 K 个可分离的 rank-one outer product；落到空间域，就是 K 个二维 convolution kernel。

这里没有压缩 mask 的几何复杂度，也没有缩小输出图像要覆盖的面积。被做成 low-rank 的是系统 operator 本身。之后每遇到一张新 mask，只需要做少量结构固定的卷积。

## 从四维求和，变成一串 FFT

对一块 rasterize 好的 mask，SOCS 的流程很规整：

mask tile **→** 一次 forward FFT **→** 逐个乘 SOCS kernel **→** K 次 inverse FFT **→** 模平方、按 eigenvalue 加权求和 **→** 得到 tile core 的 aerial image

公开的 scanner model 专利（如 US9645509B2）把这笔账写得很清楚：应用一个 K 项 TCC 模型，需要一次 mask forward FFT 加 K 次 inverse FFT，再把 K 个 complex field 的模平方加起来。

若一个 tile 有 Q 个像素，SOCS 加 FFT 的计算量大约是 O(K·Q·log Q)；直接用 TCC 则要处理 N² 个频率耦合项。两者之间的差距，正是全芯片成像能不能进入 OPC inner loop 的分界线。

Kernel 数 K 没有行业通用的常数。公开资料里几个、几十个、上百个都有，取决于 source shape、partial coherence factor σ、NA、aberration、focus、是否用 vector model，以及能接受多大误差。IBM 的 Rosenbluth 在 SPIE Advanced Lithography 2017 上讨论新的 TCC 分解时，把 10 到 100 个 kernel 当作典型预算，并指出 TCC 里有一类 near-Toeplitz 成分，来自 projection lens 锐利 aperture 边缘造成的 slope discontinuity，标准 SOCS 很难高效抓住它；他补上 non-coherent kernel 以后，1D 测试里同样 kernel 预算下的图像误差至少降了 5 倍。这也提醒我们：eigenvalue truncation 给出的是系统矩阵 norm 意义下的最佳 low-rank approximation，落到具体 layout 上，图像误差还是会挑图形。

还有一件事帮忙省掉了采样点。Mask edge 很锐，频谱可以拖得很远；但经过有限 NA 的 projection lens 以后，aerial image 是 band-limited 的。理想 scalar 模型里，强度图像的最高 spatial frequency 是 2NA/λ，满足 Nyquist 的 grid 间距约为 λ/(4NA)。以 ASML/Brion 的 scanner model 专利（US9645509B2）里的例子：λ=193 nm、NA=0.85 时，critical sampling 间距是 56.76 nm，实际 aerial image pixel 取 40 nm 左右，留出 oversampling 余量。

所以开头那张 10 nm 的全芯片 grid 并不必要。工具可以在符合光学带宽的主 grid 上算 aerial image，再靠 anti-aliasing 的 mask rasterization、interpolation 和 contour extraction 恢复 sub-pixel 的 edge 位置。要分辨 nm 级的 EPE（edge placement error），不需要把全芯片每个像素都缩到 1 nm。

FFT 也不是唯一的走法。传统 model-based OPC 往往只在 edge 的 control point 上算 EPE，没必要生成 dense image。Cobb 的实现利用卷积的线性，把局部 polygon 拆成 edge，预先存好每类 edge 对每个 kernel 的贡献。一次强度计算就变成了 lookup 局部轮廓、复数求和、取模平方、加权，复杂度只和 kernel 数及局部窗口里的 edge 数成正比。


![Edge 查表：polygon 拆成 edge 的线性组合，每个 lookup 条目是 edge 区域与 kernel 的卷积](/assets/images/wechat/tcc-socs-12.png)

图 5 Edge 查表：polygon 拆成 edge 的线性组合，每个 lookup 条目是 edge 区域与 kernel 的卷积
图源：Cobb，UC Berkeley 博士论文（1998），Figure 3.8、3.9

Dense ILT 喜欢 pixel grid、FFT 和 GPU；edge-based OPC 喜欢局部轮廓、sparse sampling 和 lookup table。两者借的是同一个 SOCS 结构，只是后面的计算载体不同。

## 全芯片也不会做一张巨型 FFT

Low-rank 只解决了"每次成像怎么算"，芯片面积还摆在那里。

生产工具会把 layout 切成许多 tile。Tile 不能沿边界生切，因为 core 里某一点的光强还受周围 mask 图形影响。计算时要把四周一圈 halo 一起读进来，只保留中间 core 的结果，最后把各块 core 拼回全芯片（重叠 tile 的做法在 US10671052B2 等专利里有描述）。

带 halo 的 tile **→** SOCS 成像 **→** 丢掉 halo 区结果 **→** 保留 tile core **→** full-chip stitching


![Tile、halo 与 core：halo 只参与计算、不输出；该专利还在 core 与 halo 之间加了加权 transition region](/assets/images/wechat/tcc-socs-13.png)

图源：TSMC 专利 US10671052B2，FIG. 6

Halo 的宽度由有效的 optical interaction range 和误差预算决定。这里要留点分寸：衍射 kernel 在数学上通常拖着长尾，并不存在一条"跨过去影响就归零"的边界。工程上是选一个足够大的窗口，把窗口外的残余压到 sign-off tolerance 以内。窗口越宽，精度越高，计算量和数据搬运也越大。

分块以后，并行性自然就出来了。不同 tile 可以交给不同节点；同一个 tile 里的不同 SOCS kernel 可以并行；不同 focus、dose 和 field position 的模型组也可以并行。FFT、逐点复数乘法、取模平方和 reduction 都是规则的数组运算，很适合专用硬件和 GPU。Cao 等人 2005 年那篇 Tachyon 全芯片仿真的论文，就已经把算法、软件、集群架构和专用加速硬件放在同一个系统里讨论。今天换成了 GPU，计算的形状并没有突然变成另一门学问。NVIDIA 在 cuLitho 页面上给的口径是 ILT 约 40 倍加速，这个数字来自厂商，实际收益要看具体流程和对比基线。

还有一笔容易漏掉的复用。Cobb 的 OPC 架构面对的是数百万次局部 mask 扰动，所以专门让强度计算只读 control point 附近的局部轮廓。今天的商业工具具体怎么利用 hierarchy、cache 和局部增量更新，公开细节不多。能确定的是，TCC/SOCS 只提供可复用的物理核心，数据展开、搬运和任务调度依然决定着全芯片的吞吐。

## "全芯片"三个字要读准

Full-chip imaging 的意思是：同一套 calibrate 过的 compact model 能覆盖整层 layout，并且在 tile 边界、field position 和工艺条件之间都把误差控制住。它不等于把整颗芯片装进一个数组，做一次前所未有的超大 FFT。

它也不等于在每个图形旁边重新解一遍三维 Maxwell 方程。Rigorous EM solver 通常只用于代表性结构、局部模型生成或 calibration。到了生产 apply 阶段，三维 mask 效应会被压进 edge、corner、局部图形或与入射角相关的 compact 响应，再接到全芯片光学模型上。

这也暴露了经典 Hopkins/SOCS 的一个重要边界：标准推导假设 mask transmission 与照明入射角可以分离。Thin mask 下这个假设很好用；但在 thick mask、oblique incidence、EUV 和 High-NA 场景里，同一个图形对不同 source point 会给出不同的 complex amplitude 和相位，一个 mask spectrum 加一套全局 TCC 就可能不够了，需要 hybrid Hopkins-Abbe、按入射角分组、vector TCC，或兼容 Mask3D 的 compact model（近年有专门研究 Mask3D 兼容的 full-vector Hopkins 成像）。

Field dependence 也会打破"一套 kernel 走遍全场"的想象。Scanner slit 不同位置的 aberration 和 pupil 响应都会变，工业实现可以给不同 field point 建多套 TCC，再按 tile 位置选择或插值。Focus、dose、polarization 和 process window 一展开，模型组数还会继续往上乘。

所以，一条全芯片成像链至少有四类误差预算：

1. TCC 做 SOCS truncation 时丢掉了多少 mode。
2. Kernel 作用窗口和 tile halo 截掉了多少长尾。
3. Mask rasterization、edge lookup 和 interpolation 引入了多少数值误差。
4. Compact resist model 和 Mask3D model 离真实工艺还有多远。

把其中一项压得极低，替不了另外三项。生产模型追求的是总误差、吞吐和内存之间的平衡，而且这份平衡要经过 wafer 数据 calibration 和独立图形验证。

## 回到那 4 万亿个点

全芯片成像算得动，没有哪一步把 20 mm 的芯片变小了。

Hopkins 先把与 layout 无关的 source 和 lens 计算挪到循环外；SOCS 再把四维的频率耦合降成少量二维 coherent convolution；FFT、edge lookup 和 sparse sampling 把卷积做快；tile 加 halo 把大面积问题切成误差可控的小块；集群、专用硬件和 GPU 最后接住这些彼此独立、结构规整的任务。

TCC/SOCS 并没有粗暴地少算一些像素。它重新组织了计算：昂贵的部分可以预计算，重复的部分可以复用，巨大的 layout 可以分块，剩下的工作可以并行。

"全芯片"这三个字，最终落在成千上万个误差可控的局部任务上。每一块都沿用同一套物理近似，最后稳稳地拼回去。
